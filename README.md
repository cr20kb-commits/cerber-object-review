# CERBER — Object Review

[English](README.en.md) · [Как помочь](CONTRIBUTING.md) · [Первые задачи](VOLUNTEER_TASKS.md)

Независимый open source модуль CR20KB для аккуратной проверки гипотез о
предметах из публичных карточек [Europol Trace an Object](https://www.europol.europa.eu/stopchildabuse).
Проект **не связан с Europol, не является его партнёром и не заявляет об одобрении Europol**.

Текущая версия — офлайн-инструмент проверки структуры записей и подготовки
локальной заметки для человека. Он не распознаёт изображения, не ищет товары
автоматически и не устанавливает личности. Windows-сканер CERBER не входит в этот репозиторий.

## Запуск

Нужен Python 3.10 или новее. Сторонних зависимостей, API-ключей и платных сервисов нет.
Из корня клонированного репозитория:

```console
python -m trace_object demo
python -m trace_object validate examples/known-object.json
python -m trace_object validate examples/insufficient-data.json
python -m trace_object report examples/known-object.json
python -m unittest discover -s tests -v
python tools/audit_publication.py
```

На Windows вместо `python` можно использовать `py -3`.
`report` создаёт новый файл в `.local/reports/` без перезаписи существующего.
Эта папка исключена из Git; отчёт не предназначен для публичного Issue.
Команды не выполняют сетевые запросы и ничего не отправляют Europol.

## Как работать с реальной карточкой

1. Откройте актуальную официальную карточку вручную. Сверьте её ID и URL;
   существование и соответствие ID ссылка/предмет проверяет человек.
2. Храните рабочую JSON-запись только в `.local/`. Скопируйте структуру примера,
   замените `demo` на `false`, используйте официальный ID и адрес карточки.
3. В `observations` укажите только видимые свойства. Гипотезы отделяйте от
   наблюдений. Для каждого кандидата добавьте открытый товарный источник,
   совпадения, противоречия и следующий шаг проверки.
4. Проверяйте запись командой `validate`, затем читайте локальный отчёт.
   `candidate` означает неподтверждённую гипотезу; `insufficient_data` —
   полноценный результат. Численные вероятности инструмент не рассчитывает.
5. Для публичного обсуждения используйте только безопасные сведения о предмете:
   ID, официальную ссылку, краткое описание и открытые товарные источники.
   Перед отправкой Issue удалите личные данные и проверьте каждое поле вручную.
6. Существенную зацепку после проверки человеком направляйте через форму
   **на официальной карточке Europol**, с указанием ограничений и использования ИИ,
   если он применялся. [Общая официальная форма](https://www.europol.europa.eu/stopchildabuse/can-you-help).
   Репозиторий и его Issues не являются каналом передачи сведений следствию.

## Ограничения и правила

- Не публикуйте личные данные, предполагаемых подозреваемых, адреса потерпевших,
  изображения людей или обвинения. Не ищите исходные материалы насилия.
- Совпадение товара не устанавливает человека; рынок продаж не доказывает место съёмки.
- Не дорисовывайте детали генеративным улучшением. Размеры без масштаба неизвестны.
- Не загружайте автоматически изображения Europol или продавцов: публичный доступ
  не означает права на копирование. Здесь нет чужих изображений и логотипов.
- Нет проверки истинности текста, прав, доступности ссылок и отсутствия всех личных данных.
  Валидатор проверяет структуру, а не безопасность публикации. Человек обязан проверить текст.
- Нет массового импорта, мониторинга, OCR, LLM, поиска совпадений или автоматической отправки.
  Официальный пилот с реальным изображением пока не выполнен.

Примеры вымышлены, не относятся к делам и не являются реальными зацепками.
В `known-object.json` известный предмет задан автором сценария; результат не доказывает
работу распознавания. `example.invalid` — намеренно несуществующий демонстрационный источник.

# Воспроизводимый пилот / Reproducible pilot

Протокол использует существующий `schema_version: 1` без изменения его контракта.
Оболочка пилота сохраняет происхождение изображения, журнал запросов и все
рассмотренные кандидаты, включая отклонённые при итоге `insufficient_data`.
Все материалы реального пилота остаются в `.local/`; этот документ содержит только процесс.

## Кто выполняет этапы / Responsibilities

| Этап | Программа | Codex / оператор | Человек |
| --- | --- | --- | --- |
| Выбор карточки | Нет сетевого импорта | Открывает текущий официальный список и одну карточку; сверяет ID/URL/дату | Проверяет при необходимости |
| Права и получение | Не скачивает изображения | Читает условия, сохраняет один разрешённый фрагмент локально вручную | Решает вопрос разрешения при неясных правах |
| Происхождение | SHA-256 и размер предоставленного файла | Записывает URL, время UTC, основание использования, преобразования | Проверяет происхождение при существенной зацепке |
| Видимые признаки | Нет OCR, зрения или LLM | Рассматривает исходник; отделяет видимое от вариантов чтения | Независимо проверяет спорные буквы и признаки |
| Поиск и сравнение | Не делает поиск | Выполняет и записывает точные запросы, открывает источники и сравнивает рисунок | Подтверждает значимого кандидата и альтернативы |
| Отчёт | Валидирует запись и байты; формирует TXT | Вводит основания решений и ограничения | Принимает решение о сообщении Europol |
| Отправка | Нет | Не отправляет автоматически | Отправляет через официальную карточку после проверки |

The program validates local records and byte integrity. Codex or another operator
performs visual analysis, searches and comparisons. A human independently verifies
substantial leads and decides whether to submit them. No automatic recognition,
source authentication, web search, redaction or Europol submission is implemented.

## Порядок работы

1. Проверьте текущий официальный список в браузере. Выберите ровно одну карточку,
   запишите ID, URL, дату публикации/обновления и дату проверки наличия в списке.
   Поисковая выдача сама по себе не подтверждает актуальность.
2. Прочитайте условия Europol и права конкретного материала. Если допустимо частное
   использование, сохраните выбранную опубликованную веб-версию в `.local/pilots/<ID>/`.
   Не ищите исходные материалы насилия, людей и адреса. Не включайте файл в Git.
3. Сразу вычислите хеш и размер. Для примера команда использует **ваш локальный** файл:

   ```console
   python -m trace_object fingerprint .local/pilots/ID/fragment.webp
   ```

4. Запишите происхождение, фактическое время окончания получения и права. Хеш
   удостоверяет совпадение локальных байтов с записью; он не удостоверяет сайт,
   изображённый предмет или дату. Сохраняйте исходный файл неизменным.
5. Сначала опишите признаки исходника. Все неуверенные чтения храните как альтернативы.
   Не добавляйте невидимые детали. Допустимые инспекционные crop/resize фиксируются
   координатами и методом интерполяции. Генеративная реконструкция не допускается.
6. Выполните ограниченный поиск по признакам. Для **каждого фактического** запроса
   запишите точную строку, тип поиска, дату и результат. Запланированный запрос нельзя
   выдавать за выполненный. Для объединённой выдачи пометьте пакет: не приписывайте
   конкретный результат отдельному запросу без доказательств. Сам файл журнала
   является записью оператора, а не доказательством работы поискового движка.
7. Просмотрите страницы и изображения выбранных товаров. Для каждого кандидата
   сохраните ссылки, совпадения, противоречия, решение, основание и следующий шаг.
   Поисковая картинка, её автоматическая подпись и текст продавца не заменяют просмотр.
   Не копируйте автоматически внешние изображения в материалы публикации.
8. Заполните оболочку по синтетическому `examples/pilot-insufficient.json`, заменив
   демонстрационные данные своими **локальными** данными. Затем:

   ```console
   python -m trace_object pilot-check .local/pilots/ID/pilot.json .local/pilots/ID/fragment.webp
   python -m trace_object pilot-report .local/pilots/ID/pilot.json .local/pilots/ID/fragment.webp
   ```

9. Прочитайте новый TXT из `.local/reports/`. При отсутствии различительных совпадений
   используйте `insufficient_data`; отклонённые модели сохраняются в `comparisons`.
   Если поиск выполнен, но кандидаты не найдены, допустим `comparisons: []` при
   `record.outcome: insufficient_data` и непустом журнале `searches`. Не создавайте
   фиктивного кандидата для прохождения валидации. Сам журнал не доказывает выполнение поиска.
   Проверка человеком и отправка сведений остаются отдельными действиями.

Replaying `pilot-check` and `pilot-report` with the saved manifest and original file
reproduces validation and report content. It does **not** rerun internet searches or
prove their execution. Search ranking and page contents can change. Record inspected
URLs and access dates; distinguish live, cached and unavailable sources.

## Оболочка / Envelope contract

UTF-8 JSON, до 256 KB. Все поля обязательны; неизвестные поля отклоняются.

| Поле | Контракт |
| --- | --- |
| `format_version` | integer `1`, версия оболочки, не замена версии вложенной записи |
| `record` | существующая запись `schema_version: 1`, см. RECORD_FORMAT.md |
| `provenance` | `image_url`, `retrieved_at` (ISO-8601 UTC), `sha256` (64 lowercase hex), `byte_length` (>0 integer), `rights_note`, `processing` (непустой массив строк) |
| `searches` | 1–100 объектов: `query`, `kind` (`web_search` / `web_image_search`), `executed_on` (`YYYY-MM-DD`), `result_note`, `sources` (массив HTTPS URL, может быть пустым) |
| `comparisons` | 0–50 объектов: `name`, `sources`, `matches`, `contradictions`, `decision`, `reason`, `next_checks`; пустой список разрешён только при `insufficient_data` и непустом журнале выполненного поиска |
| `conclusion` | явный ограниченный вывод, включая «недостаточно данных» при слабых результатах |

`decision`: `rejected` — показанный вариант отклонён; `inconclusive` — оценить не удалось;
`retained` — сохранённая гипотеза для дальнейшей проверки, **не подтверждённое изделие**.
При `retained` вложенная запись должна иметь исход `candidate` и непустые `leads`.
В `comparisons` массивы источников, совпадений, противоречий и следующих шагов непустые.
Если противоречия или совпадения не установлены, напишите это явно.
Для реального изображения допускается официальный URL Europol под `/cms/sites/default/files/`;
публичный параметр image-style может оставаться в URL. Программа его не загружает.
Прочие source URL сохраняют ограничения существующего контракта.

An empty `comparisons` list is valid for `insufficient_data` when an executed search
is logged but no candidates were found. `searches` must still contain a valid entry;
a `candidate` result still requires a comparison. Never invent a placeholder candidate.

Синтетический пример использует контрольные **текстовые байты**, не изображение дела:
`Synthetic fixture only. Not a case image.` с завершающим LF. Тесты создают их сами.
Его выдуманный запрос не выполнялся в интернете; это явно указано в примере.

## Проверки разработки

```console
python -m unittest discover -s tests -v
```

Тесты проверяют повреждение байтов, несогласованные решения, неверные даты/URL и
сохранение отклонённых кандидатов в отчёте. Для публичного PR включайте только код,
общий процесс и полностью синтетические тесты. Материалы пилота, товарные сравнения
по делу, скриншоты и отчёты не должны оказаться в индексе.
